## 0. 이 계획의 성격

다섯 건 중 **넷은 새 기능이 아니라 기존 계약의 미준수를 고치는 일**이다.
`docs/deterministic-gates.md`는 이미 "exit code가 판정"이라고 선언했고, `docs/hooks-reference.md`는 "기계적 실패에만 non-zero"라고 선언했다.
문제는 선언이 있는데 **구현이 그 선언을 지키지 않는 지점**과, **선언이 미치지 않는 지점**이 있다는 것이다.

그래서 이 계획의 검증 기준도 새로 만들지 않는다 — 기존 `pytest` + `lint_skills.py` + `check_phase.py`의 exit code를 그대로 쓴다.

### 순서의 근거

```
Phase A ──→ Phase B ──→ Phase C
(계약 정합)   (새 판정축)   (밀도 개편)
 #1 #5        #2 #4         #3
```

- **A가 먼저**: 기계적이고 되돌리기 쉽다. 여기서 CI가 깨지면 뒤를 진행하지 않는다.
- **C가 마지막**: CLAUDE.md 개편은 삭제가 아니라 **SoT 포인터로 교체**하는 작업이다. 포인터가 가리킬 문서(#4의 서브에이전트 계약, #2의 정책 게이트)가 확정된 뒤에 써야 두 번 쓰지 않는다.

## Phase A — 기존 계약 정합 (v0.6.3)

### A-1. 훅 exit code를 Claude Code 실제 의미에 맞춘다

**목표**: 차단해야 할 에러가 실제로 차단되게 한다.

**현재 상태 (실측)**

| 위치 | 내용 |
|---|---|
| `hooks/validate-assets.sh:7` | `# exit 1 = blocking error (build-breaking issues...)` ← 사실과 다름 |
| `hooks/validate-assets.sh:107` | `ERRORS (Blocking)` 출력 후 `exit 1` |
| `hooks/validate-commit.sh` / `validate-push.sh` | `exit 2` ← 올바름 |
| `docs/hooks-reference.md:115` | "Stay advisory. Exit 0... Reserve **non-zero** for unambiguous, mechanical failures (invalid JSON)" |

Claude Code 훅에서 `exit 2`는 stderr를 **Claude에게** 되돌려 주고, `exit 1`은 사용자에게만 보이고 흘러간다.
`validate-assets.sh`는 PostToolUse 훅이므로(`plugin.json:64-72`) 도구는 이미 실행된 뒤다 —
**"Claude가 깨진 JSON을 고치게 만드는 유일한 경로가 exit 2**"이고, 지금은 그 경로가 끊겨 있다.
`hooks-reference.md`의 의도("기계적 실패에는 non-zero")는 맞았고, 숫자만 모호하게 남겨둔 것이 원인이다.

**변경**

1. `hooks/validate-assets.sh:107` — `exit 1` → `exit 2`
2. `hooks/validate-assets.sh:6-7` 헤더 주석 — 4코드 계약(`deterministic-gates.md`)과 같은 표현으로 재작성
3. `docs/hooks-reference.md` 규칙 3 — "non-zero" → **"`exit 2`. `exit 1`은 Claude에게 전달되지 않으므로 차단 의도로 쓰지 말 것"**
4. `docs/hooks-reference.md`에 **훅별 판정 능력 표** 신설 — 아래 실측 결과를 그대로 표로

   | 훅 | 최대 exit | 판정 능력 |
   |---|---|---|
   | `validate-commit.sh` · `validate-push.sh` | 2 | 차단 가능 |
   | `validate-assets.sh` | 2 (수정 후) | 차단 가능 |
   | `validate-skill-change.sh` · `unity-meta-check.sh` · `unity-animator-string-lint.sh` · `detect-gaps.sh` | 0 | **경고 전용 — 판정 아님** |
   | `post-compact.sh` · `notify.sh` | exit 문 없음 | **경고 전용 — 판정 아님** |

   > 이 표가 필요한 이유: 판정을 낸 적 없는 훅이 "통과"로 읽히는 것을 막는다.
   > `deterministic-gates.md`가 이미 "A gate that cannot run is not a gate that passed"라고 쓴 것의 훅 버전.

**검증**

```bash
python3 -m pytest tests/test_hooks_layout.py -q      # exit 0 이어야 함
```

기존 테스트는 `returncode == 0` 케이스만 단언하므로 이 변경으로 깨지지 않는다(실측 확인).
**단, 회귀 방지 테스트를 새로 추가한다** — `tests/test_hooks_layout.py`에:

```python
def test_invalid_json_blocks_with_exit_2(unity):
    """exit 1 은 Claude 에게 전달되지 않는다. 차단은 exit 2 여야 한다."""
    write(unity, "Assets/Data/items.json", "{ broken")
    result = run_hook(VALIDATE_ASSETS, unity, stdin=write_event("Assets/Data/items.json"))
    assert result.returncode == 2
    assert "not valid JSON" in result.stderr
```

**리스크**: 낮음. 되돌리기 = 한 글자 revert.
**주의**: JSON 검사가 이제 실제로 차단되므로, 기존 프로젝트에 깨진 JSON이 있으면 처음으로 표면화된다. CHANGELOG에 명시.

### A-2. 스킬 description 오선택 게이트

**목표**: 스킬 85 + 에이전트 45 = 130개 선택지 중 **모델이 잘못 고르는 것**을 스크립트가 잡는다.

**현재 상태 (실측)**

`scripts/lint_skills.py`는 이미 잘 만들어져 있다 — 7개 정적 검사, `--strict`, `--quiet`, **baseline 메커니즘**(`scripts/lint_baseline.json`), CI 연동, `tests/test_skill_lint.py`.
그런데 description에 대해서는 **비어 있는지만** 본다(`L193: if not fm.get("description", "").strip()`).

`description`은 Claude가 스킬 자동 발동을 결정할 때 읽는 **라우팅 지시문**이다.
「툴 스키마가 에이전트를 가른다」의 지적: 기능 나열만 있고 "**언제 쓰지 않는지**"가 없으면 모델은 추론하고, 운영에서 추론은 설계 실패다.

**변경** — `scripts/lint_skills.py`에 검사 3종 추가

| 검사 | 판정 | 등급 |
|---|---|---|
| **C8. 부정 조건 부재** | description에 `Do NOT` / `않` / `아닌` / `instead of` 계열 표현이 없음 | WARNING |
| **C9. 근접 중복** | 다른 스킬과 description 토큰 집합 Jaccard 유사도 ≥ 0.6 | WARNING |
| **C10. 모호 트리거** | description이 "helps with", "도와줍니다", "관련 작업" 류 동사로만 구성 | WARNING |

**전부 WARNING 등급으로 시작한다.** 이유:

- 85개 스킬 중 상당수가 즉시 걸릴 것이고, 한 번에 다 고치는 것은 이 계획의 범위가 아니다
- 이 저장소에는 이미 **baseline 메커니즘**이 있다 — 기존 실패는 baseline에 기록해 CI를 녹색으로 두고, **새로 추가되는 스킬만 즉시 차단**한다. 정확히 이 상황을 위해 만들어진 장치다

```bash
python3 scripts/lint_skills.py skills/ agents/ --write-baseline   # 1회
```

**검증**

```bash
python3 -m pytest tests/test_skill_lint.py -q                              # 신규 검사별 케이스 추가
python3 scripts/lint_skills.py skills/ agents/ --baseline scripts/lint_baseline.json   # exit 0
python3 scripts/lint_skills.py skills/ agents/ --strict                    # exit 1 예상 (부채 가시화)
```

**리스크**: 중간. C9(유사도 0.6)는 임계값이 자의적이다.
→ 완화: `deterministic-gates.md` "Adding a gate" 규칙 2에 따라 **임계값을 파일 상단 명명 상수로** 두고, 최초 실행 결과를 보고 조정한다. 조정 근거는 커밋 메시지에 남긴다.

## Phase B — 새 판정축 (v0.7.0)

### B-1. unsafe-success — 완료 축과 정책 축을 분리한다

**목표**: "일은 끝났는데 규칙을 어겼다"를 exit code로 잡는다.

**문제**

현 exit 0/1/2/3은 전부 **"게이트가 돌았나 / 무엇을 말했나"** 축이다.
CLAUDE.md "Don't do this"(팩 위반 스폰, `--no-verify`, 규약 밖 경로)는 **문장으로만 존재하고 판정 주체가 없다.**
그 결과 다음이 전부 `exit 0`으로 기록된다:

- 테스트를 `skip` 처리하고 통과시킨 story-done
- `--no-verify`로 훅을 우회한 커밋
- game 프로젝트인데 `product/prd/` 산출물이 생성됨 (팩 혼용)

「성공도 실패로 쪼개야 한다」의 지적: completion rate 단독은 unsafe-success를 가리고, **다음 세션의 에이전트가 그 경로를 정상 패턴으로 학습한다.**

**변경** — `scripts/verify_policy.py` 신설 (표준 라이브러리만, 4코드 계약 준수)

검사 대상은 **관측 가능한 흔적**으로만 한정한다. 런타임 행동(어떤 에이전트를 스폰했는가)은 스크립트가 볼 수 없으므로 시도하지 않는다.

| ID | 검사 | 판정 |
|---|---|---|
| P1 | 스토리가 `Status: Complete`인데 `Test Evidence`가 가리키는 경로에 파일이 없음 | 2 (abort) |
| P2 | 대상 diff에 skip 마커가 **추가**됨 (`@pytest.mark.skip`, `.skip(`, `[Ignore]`, `xfail`) | 2 (abort) |
| P3 | `PROJECT_TYPE`과 어긋나는 트랙의 산출물이 존재 (game 프로젝트에 `product/prd/`, web 프로젝트에 `design/gdd/`) | 1 (warning) |
| P4 | 생성 파일이 CLAUDE.md "File conventions" 밖 경로 | 1 (warning) |
| — | 저장소가 git이 아님 / diff 산출 실패 | 3 (cannot judge) |

**호출 지점**: `skills/story-done` — 완료 판정 직전. 완료 축(기존 AC 검증)과 **독립적으로** 실행하고, 결과를 2축으로 보고한다.

```
Task completion : PASS  (AC 7/7)
Policy compliance: FAIL  (verify_policy.py → exit 2, P2: tests/test_combat.py 에 @pytest.mark.skip 추가됨)
→ 스토리를 Complete 로 표시하지 않는다.
```

**설계 제약** (`deterministic-gates.md` "Adding a gate" 준수)

1. exit 0/1/2/3만
2. 모든 임계값·패턴을 파일 상단 명명 상수로
3. *왜* 실패했는지 출력 (P-ID + 파일 경로)
4. 정보성 신호는 exit code에 넣지 않음
5. 표준 라이브러리만
6. `.github/workflows/test.yml`에 추가 — **⚠️ 이 파일은 `device_commit_files`에서 보호 대상이다. `device_bash`로 편집할 것**

**검증**

```bash
python3 -m pytest tests/test_verify_policy.py -q   # 신규. P1~P4 + exit 3 케이스
python3 scripts/verify_policy.py --self-test       # 픽스처 기반
```

**리스크**: 중간~높음. 오탐이 나면 사용자가 게이트를 통째로 신뢰하지 않게 된다.
→ 완화: **P1·P2만 exit 2, P3·P4는 exit 1로 시작.** 오탐 보고가 없으면 다음 마이너에서 승격.
「품질 게이트는 hooks다」의 경고 — 게이트가 과하면 `disableAllHooks`로 우회당한다.

### B-2. 서브에이전트 4줄 계약

**목표**: 팬아웃의 격리 이득이 반환 단계에서 새는 것을 막는다.

**현재 상태 (실측)**

`rules/subagent-collaboration.md`는 §1~§7로 잘 구성되어 있지만 두 가지 공백이 있다.

1. §3 "prompt 의무 항목" 5개 — 프로젝트 컨텍스트 / 외부 조사 / 안건 / 결정 권한 / 응답 형식.
   **"금지"(무엇을 읽거나 수정하지 않을 것)와 "반환 경계"(무엇을 main context에 올리지 않을 것)가 없다.**
   그래서 서브에이전트가 폐기한 후보와 실패 로그까지 main으로 되돌려 보낸다 — 격리하려던 것이 그대로 돌아온다.
2. 문서 전체가 **게임 트랙 전용**이다. §2의 표준 4분야가 `game-designer` / `ux-designer` / `ui-programmer` / `gameplay-programmer`로 고정되어 있다. v0.4.0에서 product 팩이 들어왔는데 이 규칙은 따라오지 않았다.

**변경**

1. **§3에 항목 6·7 추가**

   ```markdown
   6. **금지 영역** — 읽지 않을 것 / 수정하지 않을 것 / 스폰하지 않을 것.
      (예: "테스트 파일을 수정하지 마세요. 실패는 보고만 하세요.")
   7. **반환 경계** — main context 에 올릴 것 / 올리지 않을 것.
      기본값: 폐기한 후보, 중간 탐색 로그, 실패한 시도는 올리지 않는다.
      반환값은 요약문이 아니라 **Artifact(파일 경로 + 상태)** 로 낸다.
   ```

2. **§2를 트랙 중립으로** — 표준 4분야를 game/product 두 세트로 분리
   (product: `product-manager` / `ux-designer` / `frontend-engineer` / `backend-engineer`)
3. **§5 안티패턴에 1줄 추가** — "❌ 서브에이전트가 탐색 과정 전체를 서술해 반환 — 오케스트레이터가 장문 서사에 설득된다"

**검증** — 이 항목은 규칙 문서라 스크립트 판정이 어렵다. 대신:

```bash
python3 scripts/lint_skills.py skills/ agents/ --baseline scripts/lint_baseline.json
grep -c "game-designer" rules/subagent-collaboration.md   # 트랙 중립화 확인
```

정성 검증: `rules/subagent-collaboration.md`를 읽지 않은 서브에이전트에게 §3만 주고 프롬프트를 쓰게 해, 6·7 항목이 실제로 채워지는지 1회 확인.

**리스크**: 낮음. 규칙 추가이므로 기존 동작을 깨지 않는다.

## Phase C — CLAUDE.md 밀도 개편 (v0.7.0)

### C-1. 214줄 → 약 120줄, 그리고 비어 있던 유형2를 채운다

**목표**: 삭제가 아니라 **SoT 포인터로 교체** + **구현 편향 교정 8줄 신설**.

**작업 1 — 압축 (약 95줄)**

| 대상 | 처리 |
|---|---|
| 32–90 스테이지별 에이전트·스킬 목록 (59줄) | `docs/workflow-catalog.yaml`이 SoT. 트랙별 4~5줄 요약 + 포인터로 교체 |
| 100–118 Key workflows (19줄) | 동일. `/help`·`/project-stage-detect`가 이미 `check_phase.py`로 판정 |
| 171–190 File conventions (20줄) | `ls`로 확인 가능. **"빈 폴더를 미리 만들지 말 것" 1줄만 유형2이므로 남긴다** |
| 204–214 Reference docs (11줄) | 삭제. `ls docs/`로 확인 가능 |

**유지 (건드리지 않음)**: Domain packs(9–31) · Agent usage rules(91–99) · Deterministic gates(132–154) · Route hint(155–170) · Don't do this(191–198).
특히 132–154는 이 저장소의 정체성이므로 한 줄도 줄이지 않는다.

**작업 2 — `## 작업 원칙` 8줄 신설 (문서 최상단)**

CLAUDE.md의 유형2 항목이 전부 오케스트레이션 편향이고 **구현 편향 교정이 0줄**이다.
`rules/` 코드 규칙 15종이 있지만 path-scoped라 압축 후 사라진다.

원문 8줄을 그대로 쓰되 **2번은 뒤집는다** — 이 저장소는 사용자가 설치하는 배포물이고, 스킬 이름·슬래시 명령·산출물 경로 규약은 사실상 공개 API다.

```markdown
# 작업 원칙

- 해결책을 설계하기 전에, 이미 자리 잡은 제품들이 같은 문제를 어떻게 푸는지
  먼저 살펴보세요. 접근 방식을 처음부터 발명하지 말고 검증된 패턴을 채택하세요.
- 스킬 이름·슬래시 명령·산출물 경로 규약의 하위 호환을 깨지 마세요. 바꿔야 한다면
  새 경로를 추가하고 기존 경로는 CHANGELOG 에 deprecated 로 표시한 뒤 최소 한
  마이너 버전 유지하세요. 반면 플러그인 내부 구현(스크립트 헬퍼, 훅 lib, 템플릿
  내부 구조)에는 호환 레이어를 쌓지 말고 쓰이지 않는 경로를 삭제하세요.
- 현재 요구사항을 완전히 충족하는 가장 단순한 구현을 선택하세요.
```

### Phase C 후기 — 줄 수 목표(130)는 틀린 목표였다

착지점은 **214 → 169줄**이다. 목표를 못 맞췄고, 목표 쪽이 틀렸다고 판단한다.

130이라는 숫자는 "스테이지 표 59줄은 `workflow-catalog.yaml`에 있으니 지우면 된다"는
전제로 계산했다. 실제로 확인해 보니 **카탈로그에 에이전트 정보가 사실상 없었다**
(`grep -c agent docs/workflow-catalog.yaml` → 2). 스테이지별 primary/support 배정은
`agent-packs.yaml`에도 없었고, 오직 CLAUDE.md 본문에만 존재했다 — 즉 유형1(스스로
알아낼 수 있음)이 아니라 **유형3(팀의 선택)** 이었고, 지웠으면 복원되지 않았다.

그래서 삭제가 아니라 **이관**했다(→ `agent-packs.yaml` `stages:`). 이관하면
CLAUDE.md에는 "누가/무엇을 어디서 찾는가"를 설명하는 포인터 절이 남고, 그게 21줄이다.
여기에 계획에 명시했던 `## 작업 원칙` 13줄이 더해진다. 130은 이 둘을 계산에 넣지
않은 숫자였다.

반대 해석도 적어 둔다: **169줄도 여전히 길다.** `## Deterministic gates` 23줄과
`## Route hint` 16줄은 각각 `docs/deterministic-gates.md`와 `rules/route-hint.md`에
전문이 있으므로 더 줄일 여지가 있다. 이번에 손대지 않은 이유는 계획서에서
"이 저장소의 정체성이므로 한 줄도 줄이지 않는다"고 먼저 못박았기 때문이고,
숫자를 맞추려고 그 결정을 뒤집는 것이야말로 self-loop가 경계하는 점수 인플레의
거울상이라고 봤다. 다음 라운드에서 별도로 판단할 사안이다.

**줄 수를 완료 게이트에서 뺐다.** 밀도는 목적이고 줄 수는 그 대리 지표인데,
대리 지표를 게이트로 걸면 지표를 맞추려 목적을 훼손하게 된다. 대신 정보 손실
여부를 직접 판정하는 게이트를 남겼다 — `tests/test_agent_packs_stages.py`.
