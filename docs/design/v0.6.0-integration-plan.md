## 0. 세 줄 요약

im-not-ai에서 가져올 것은 한글 윤문 기능 하나가 아니라 **"LLM 자기 채점을 코드 판정으로 바꾸는 아키텍처"** 전체입니다. 현재 claude-code-studios의 모든 게이트(`/gate-check` · `/smoke-check` · `/story-done` · `/self-loop`)는 예외 없이 LLM이 스스로 매긴 점수로 PASS/FAIL을 정하고 있고, 리포에는 테스트도 CI도 LICENSE 파일도 없습니다. im-not-ai는 정확히 그 자리에 exit code 기반 스크립트·골든 픽스처·GitHub Actions를 갖고 있습니다.

따라서 이번 통합은 **기능 추가 1건 + 기반 공사 3건**입니다. 기능은 한글 윤문 스킬(신규 `writing` 팩), 기반은 결정적 게이트·비용 라우팅·테스트/CI입니다. 업로드하신 스킬 3종은 `game` 팩 콘텐츠로 별도 편입하되, 프론트매터 규약이 달라 수술이 필요합니다.

버전은 **v0.6.0**입니다. 초안은 v0.5.0을 제안했는데 — 로드맵의 v0.5.0 항목("Claude Code Studios 리네임")이 커밋 `324fef1`에서 처리돼 슬롯이 비었다는 판단이었습니다 — 그 사이 **Lesson Ledger가 v0.5.0(2026-07-15)으로 슬롯을 채웠습니다**(머지 `f2d4a1f`, `plugin.json` 0.5.0). 신규 팩 1개 + 스킬 6개 + 리포 최초의 Python·CI 도입은 minor 이상의 변화이므로 v0.6.0으로 밉니다.

## 1. 먼저 알아야 할 사실 5가지

계획을 읽기 전에 이 다섯 개를 알고 계셔야 뒤의 결정들이 이해됩니다.

**첫째, studios에는 LICENSE 파일이 없습니다.** `plugin.json`과 `marketplace.json`은 `"license": "MIT"`를 선언하는데 실제 라이선스 본문이 리포 어디에도 없습니다. MIT 코드를 vendor copy 하려면 원저작자 고지를 넣어야 하는데, 넣을 파일 자체가 없는 상태입니다. 이건 통합의 전제 조건이라 Phase 0에서 먼저 해결합니다.

**둘째, 스킬 부속 파일 규약은 이미 열려 있습니다.** 이 문서 초안에는 "78개 전부가 단일 `SKILL.md`이므로 새 규약을 여는 것이 구조적 결정"이라고 적었는데, origin 머지 후 실측하니 틀렸습니다. `skills/web-ai-patterns/`(커밋 `2cb2bc6`)가 이미 `reference/` 하위에 3개 파일 48KB를 두고 있고, 로딩 전략까지 확립돼 있습니다 — 인자(`ai`|`monetization`|`data`)로 필요한 파일 하나만 `Read` 하고 **전량 덤프를 금지**합니다. 이건 §9에서 `humanize-korean`의 316KB 완화책으로 제안한 것과 같은 패턴이라, 새 규약을 만드는 게 아니라 **기존 선례를 따르면 됩니다.**

다만 **디렉터리 이름이 갈립니다** — studios는 `reference/`(단수), im-not-ai는 `references/`(복수)입니다. 둘 다 두면 규약이 아니라 우연이 됩니다. 선례가 이미 단수이므로 이식 시 `reference/`로 통일하고, 이때 §3.1의 경로 상수 5곳이 `.claude/` 제거뿐 아니라 **단수형 변경까지 함께** 받아야 합니다. `references/metrics_v2.py`를 import 하는 코드 경로도 같이 훑어야 합니다. (§11-1에서 확인받습니다.)

**셋째, studios 스킬·에이전트 프론트매터가 im-not-ai보다 엄격합니다.** studios 스킬은 78개 전부가 `name` · `description` · `argument-hint` · `user-invocable` · `allowed-tools` 5개 필수 필드를 갖습니다(선택 필드로 `model`, `agent`가 붙기도 합니다 — 예: `gate-check`의 `model: opus`, `web-ai-patterns`의 `agent: backend-engineer`). 에이전트 41개는 전부 `name` · `description` · `tools` · `model` · `maxTurns` 5개를 갖습니다. im-not-ai 스킬은 2~4개, 에이전트는 3개뿐입니다. 업로드하신 스킬 3종은 2개(`name` · `description`)뿐이라 **studios 자체 린터 `/skill-test static`의 7개 검사 중 3개를 확정 FAIL** 합니다. 전부 변환 대상입니다.

**넷째, `verify_gates.py`는 `tests/golden/checks.py`를 sys.path로 import 합니다.** 게이트 스크립트만 떼어 오면 import 단계에서 죽습니다. 게이트와 테스트는 한 묶음으로 가져와야 하고, 이건 오히려 잘된 일입니다 — 어차피 둘 다 선택하셨습니다.

**다섯째, 마운트된 리포에 git 쓰기가 됩니다.** 초안에는 `.git/index.lock` 생성이 `Operation not permitted`로 거부된다고 적었으나, 재확인 결과 **권한 문제가 아니었습니다.** 크래시한 git 프로세스가 남긴 0바이트 `index.lock` 잔여물이 있었고(실행 중인 git 프로세스는 없음), 이를 제거하니 커밋·머지가 정상 동작했습니다. 즉 로컬에서 직접 작업할 수 있습니다. §8의 작업 방식 선택은 이 정정에 따라 다시 썼습니다.

**Phase 0은 이미 끝났습니다.** 초안 작성 시점에 미커밋이던 self-loop 기능과 `production/` 처리는 아래까지 완료된 상태입니다.

- `abf58ba` — `.gitignore`에 `production/` 추가 (런타임 로그가 `git add -A`에 딸려 들어가는 문제 차단)
- `fe017e8` — self-loop 기능 커밋 (`rules/self-loop.md` · `skills/self-loop/` · 훅 · 문서 4종)
- `8990f47` — `origin/main` 머지. `docs/skills-reference.md`가 같은 표에 서로 다른 행을 추가한 형태로 충돌해 세 행(`/self-loop` · `/sot-audit` · `/legacy-purge`) 모두 유지로 해결. 머지로 스킬이 78개가 되어 리포 전역 카운트 문구를 실측에 동기화(스킬 78, rules 13 = 전역 2 + 경로별 11).
- 0바이트 잔여 파일 `testfile2` 삭제.

남은 Phase 0 항목은 `LICENSE` · `NOTICE.md` 생성 둘뿐입니다. 세 커밋 모두 **아직 push하지 않았습니다** (`main`이 `origin/main`보다 3 ahead).

### 3.1 경로 상수 수정 — 놓치면 전부 깨지는 지점

im-not-ai의 5개 스크립트와 `metrics_v2.py`는 references 위치를 **하드코딩**하고 있습니다:

```python
# im-not-ai (현재)
_REFS = os.path.join(_HERE, "..", ".claude", "skills", "humanize-korean", "references")

# claude-code-studios (변경 후) — .claude/ 세그먼트 제거 + references → reference 단수화
_REFS = os.path.join(_HERE, "..", "skills", "humanize-korean", "reference")
```

**실측 확인 결과 수정 대상은 정확히 5개 파일입니다** (grep으로 검증):

| 파일 | 줄 | 현재 표현 |
|---|---|---|
| `build_diagnosis_rules.py` | 48 | `os.path.join(_HERE, "..", ".claude", "skills", ...)` |
| `build_quick_rules.py` | 35 | 동일 |
| `prepare_monolith_input.py` | 54 | `PROJECT_ROOT / ".claude" / "skills" / ...` |
| `verify_change_rate.py` | 36 | `os.path.join(_HERE, "..", ".claude", ...)` |
| `verify_gates.py` | 45 | `os.path.join(_ROOT, ".claude", "skills", ...)` |

`reference/metrics_v2.py`는 `_HERE`(자기 디렉터리) 기준이라 **경로 상수 수정은 불필요**합니다 — 21행 docstring에만 경로가 언급되며 이건 문구 정리 수준입니다. `verify_gates.py`가 sys.path에 넣는 `tests/golden`은 studios에서도 경로가 같아 그대로 둡니다.

단수화(`references` → `reference`)는 위 5개 파일의 경로 상수뿐 아니라 **문자열 전수 검색으로 잡아야 합니다.** SKILL.md·에이전트 정의·테스트 픽스처·docstring 안의 `references/` 표기가 모두 대상입니다. 이식 후 `grep -rn "references/" scripts/ skills/ agents/ tests/`가 0건이면 통과로 봅니다.

이식 후 `python3 scripts/build_quick_rules.py --check`가 exit 0으로 떨어지면 경로가 맞은 것이고, 이 명령을 CI에 넣어 두면 회귀가 자동으로 잡힙니다.

## 4. 요소별 상세 설계

### 4.1 A1 — 한글 윤문 스킬 세트

**신규 `writing` 팩 도입.** 현재 팩은 core(25) · game(10) · product(7) 3개고 활성화는 `PROJECT_TYPE`으로 결정됩니다. 한글 윤문은 게임 프로젝트의 패치노트·GDD·내러티브 텍스트에도, 제품 프로젝트의 릴리스 노트·랜딩 카피·기술 문서에도 똑같이 필요합니다. 그래서 `writing` 팩은 **전 프로젝트 타입에서 활성**됩니다:

```yaml
# docs/agent-packs.yaml
activation:
  game:    [core, game, writing]
  web:     [core, product, writing]
  mobile:  [core, product, writing]
  service: [core, product, writing]
  unknown: [core, game, product, writing]

packs:
  writing:
    - name: humanize-monolith
      role: 단일 콜 한글 윤문 — 탐지·윤문·자체검증 일괄, 도구 호출 3회 캡
    - name: humanize-diagnostician
      role: 글 전체의 지배 AI 티 패턴 3~6개 진단 (standard·heavy 경로)
    - name: humanize-finalizer
      role: 원문 대조 의미 보존 15항 + 자연성 판정, 국소 보정 (heavy 경로)
    - name: korean-ai-tell-taxonomist
      role: AI 티 분류 체계 SSOT 유지·신규 패턴 승격 (유지보수 전용)
```

`writing`을 `core`에 병합하지 않는 이유는 한국어 전용 기능이기 때문입니다. 별도 팩이면 나중에 영어 대응이 필요할 때 `activation`에서 빼기만 하면 됩니다.

**에이전트 프론트매터 변환.** im-not-ai는 `name` · `description` · `model` 3필드뿐이고 studios는 41개 전부가 `tools`와 `maxTurns`를 갖습니다. 변환 예:

```yaml
---
name: humanize-monolith
description: "..."          # 원문 유지
model: opus                  # 원문 유지
tools: Read, Write           # 신규 — 도구 호출 3회 캡(Read 입력 + Read 룰북 + Write final)에 정확히 대응
maxTurns: 8                  # 신규 — 캡 3회에 여유를 준 상한
pack: writing                # 신규 — product 팩이 쓰는 필드 규약 차용
---
```

`tools`를 `Read, Write`로 좁히는 게 중요합니다. im-not-ai는 "도구 호출 3회 캡"을 **프롬프트 지시로만** 강제하는데, studios의 `tools` 필드로 좁히면 같은 제약이 **구조적으로** 걸립니다. im-not-ai가 v1.5에서 얻은 교훈("wall-clock의 진짜 변수는 모델이 아니라 에이전트 내부 도구 호출 횟수")을 프롬프트가 아니라 스키마에 박는 셈입니다. `diagnostician`도 `Read, Write`, `finalizer`는 `Read, Write, Edit`(국소 보정), `taxonomist`는 `Read, Write, Edit, Glob, Grep`.

**스킬 프론트매터 변환.** studios 5필드를 채웁니다. im-not-ai의 `disable-model-invocation: true`는 studios에 없는 필드이므로 제거하고 `user-invocable: true`로 대체합니다. 단 이건 **동작 변화**입니다 — 기존에는 `/humanize`를 명시적으로 쳐야만 발동했는데, studios 규약을 따르면 모델이 자연어에서도 호출할 수 있게 됩니다. `humanize-korean`(오케스트레이터)은 원래부터 자연어 트리거를 의도한 스킬이므로 문제없고, `humanize` · `humanize-redo`는 얇은 래퍼라 중복 발동 위험이 있습니다. **`description` 말미에 "명시적 슬래시 호출 전용" 문구를 넣어 완화**하고, 그래도 중복이 관찰되면 두 래퍼를 `humanize-korean` 하나로 접는 것을 v0.5.1 과제로 둡니다.

`humanize-korean/SKILL.md`의 비표준 `version: "2.3.0"` 필드는 유지합니다. 상류 동기화 시 어느 버전에서 갈라졌는지 추적할 유일한 표식입니다.

**`humanize-redo` 본문 수리.** 현재 본문이 v2.1에서 은퇴한 `korean-style-rewriter` · `content-fidelity-auditor`를 호출하도록 쓰여 있고, 산출물도 존재하지 않는 `02_detection.json` · `05_naturalness_review.json`을 읽습니다. 이식하면서 heavy 경로(`diagnostician` → `monolith` → `finalizer`)와 실제 산출물(`02_diagnosis.md` · `09_finalize.json`)로 갱신합니다. 이건 상류의 버그를 우리 쪽에서 고치는 것이므로 **상류 PR로 되돌려 보낼 후보**입니다.

**생성물 주의.** `reference/quick-rules.md`와 `reference/diagnosis-rules.md`는 `ai-tell-taxonomy.md`(SSOT)에서 빌드된 산출물입니다. 손으로 고치면 CI의 `--check`가 막습니다. 이 사실을 두 파일 상단 주석과 `docs/deterministic-gates.md`에 명기합니다.

### 4.2 A2 — 결정적 게이트 아키텍처

여기가 이번 통합의 실질적 핵심입니다. **두 층으로 나눠 진행합니다.**

**층 1 — 그대로 이식 (한글 텍스트 게이트).** `verify_gates.py`는 4축을 판정합니다: ① 문자 변경률(30% 경고 / 50% 중단) ② 진단 목표달성(z-score 수렴 검증) ③ 대구 전멸 방지(C-8 "A가 아니라 B" 구문을 전부 깨서 필자 목소리를 지웠는지) ④ 골든 검사 + 수치 주입 차단. exit code는 `0` 수렴 / `1` 경고 / `2` 중단 / `3` 실행 오류. 이건 한국어 문체 지표에 특화돼 있어 그대로 씁니다.

**층 2 — 패턴 일반화 (studios 전체 게이트).** 현재 studios의 판정 메커니즘을 정확히 옮기면 이렇습니다. `/gate-check`은 LLM이 파일 존재를 Glob으로 확인하고 산문으로 PASS/CONCERNS/FAIL을 씁니다. `/smoke-check`은 LLM이 테스트 러너를 Bash로 돌린 뒤 **출력을 읽고 스스로 판정**합니다. `/self-loop`은 LLM이 각 기준을 1~10점으로 자기 채점합니다. 세 곳 모두 im-not-ai가 v2.1에서 폐기한 그 구조입니다 — im-not-ai의 표현을 빌리면 *"LLM 산수는 부정확하므로 과윤문 가드 자체가 무른 상태였다."*

`/self-loop`은 이미 이 위험을 알고 방어하고 있습니다. "8점 이상은 인용된 증거가 없으면 무효", "1회차에 전부 9~10점이면 기준이 느슨한 것", 5회 상한, 2회 정체 시 중단. 좋은 방어지만 전부 **LLM에게 스스로를 의심하라고 부탁하는** 방식입니다. im-not-ai의 답은 다릅니다: 판정을 아예 LLM 밖으로 빼고, 스크립트 exit code를 SSOT로 선언합니다.

그래서 다음을 추가합니다.

- **`docs/deterministic-gates.md`** — exit code 규약(0 통과 / 1 경고 / 2 중단 / 3 판정불가)을 리포 표준으로 정의. `verify_gates.py`가 레퍼런스 구현.
- **`/self-loop` Phase 2 수정** — 채점 전에 "이 기준을 코드로 판정할 수 있는가?"를 먼저 묻고, 가능하면 스크립트를 쓰고 그 exit code가 점수를 **덮어쓴다**. 스크립트가 FAIL이면 LLM이 9점을 줘도 FAIL입니다. 불가능한 기준(가독성·톤)만 자기 채점으로 남깁니다.
- **`/smoke-check` Phase 5 수정** — 테스트 러너의 **exit code를 직접 읽어** 판정. 현재는 출력을 LLM이 파싱합니다. `NOT RUN`을 `PASS WITH WARNINGS`로 취급하는 현행 규칙은 유지하되, 러너가 non-zero면 LLM 해석 없이 즉시 FAIL.
- **`/gate-check`은 건드리지 않습니다.** 판정 대상이 "산출물이 존재하고 의미 있는 내용을 담았는가"라 본질적으로 정성적이고, 문서가 verdict를 **advisory(사용자가 최종 결정)**로 못박고 있습니다. 여기에 코드 판정을 밀어 넣으면 설계 의도를 깹니다.

이 층 2 작업은 파일 3개 수정(SKILL.md 2개 + 신규 doc 1개)으로 끝나지만, 플러그인의 신뢰도에 미치는 영향은 윤문 스킬보다 큽니다.

### 4.3 A3 — route_hint 비용 라우팅

**층 1 — 그대로 이식.** `prepare_monolith_input.py`의 라우팅 규칙은 결정적입니다:

```python
ROUTE_HEAVY_MIN_CHARS = 15000   # 초과 → heavy
ROUTE_HEAVY_MIN_TELLS = 8       # risk=high AND tells>=8 → heavy
ROUTE_LIGHT_MAX_TELLS = 2       # tells<=2 AND risk in (low,medium) → light
# 그 외 → standard
```

`tells`는 6개 정수 카운트(`conclusion_pivot` · `safe_balance` · `double_passive` · `by_passive` · `have_make_literal` · `double_particle`)의 합입니다. 주목할 점은 **z-score와 밀도 지표를 의도적으로 배제**했다는 것 — `baseline_v2.json`의 70셀이 placeholder라 신뢰할 수 없기 때문입니다. 검증되지 않은 신호를 의사결정에서 빼는 이 규율이 이식할 가치의 절반입니다.

**층 2 — 오케스트레이터 일반화 (`rules/route-hint.md`).** studios CLAUDE.md는 이미 *"에이전트가 존재한다는 이유만으로 스폰하지 마라. 작업이 단순하면 직접 처리하라"*고 적어 뒀지만, 판단 기준은 오케스트레이터의 감입니다. im-not-ai의 실측이 이 감의 비용을 정량화합니다 — 1만자 글을 7콜로 청킹하면 610K 토큰, 단일 콜이면 134K에 품질 동등. **4.5배 낭비의 원인은 청크마다 룰북과 진단을 재로드한 것**이었습니다. 41개 에이전트가 각자 컨텍스트를 재로드하는 studios에 똑같이 적용되는 구조입니다.

신규 전역 규칙은 이렇게 갑니다:

| 경로 | 신호 | 동작 |
|---|---|---|
| light | 파일 1~2개, 단일 도메인, 기존 패턴 반복 | 오케스트레이터가 직접 처리. 에이전트 스폰 0 |
| standard | 단일 도메인, 신규 설계 판단 필요 | 담당 에이전트 1개 |
| heavy | 다중 도메인 or 되돌리기 어려운 변경 or 명시적 증적 요구 | 팀 팬아웃 + 게이트 |

여기에 im-not-ai가 명문화한 두 원칙을 그대로 가져옵니다. **"절감은 모델 교체가 아니라 콜 수 축소에서 온다"**(모델 티어 강제 금지, 사용자 선택) 와 **"분할은 최후 수단"**(단일 콜 우선). 그리고 self-loop이 그랬듯 `hooks/session-start.sh`에 4줄 요약을 출력하고 `docs/rules-reference.md` 전역 규칙 표에 한 행을 추가합니다.

### 4.4 A4 — 골든 테스트 + CI

**골든 픽스처 구조.** 각 픽스처 디렉터리가 4개 파일을 갖습니다: `input.txt`(원문) · `good_output.txt`(반드시 PASS) · `bad_output.txt`(반드시 FAIL) · `expected_failures.json`(bad가 트리거해야 할 실패 코드 목록). 테스트는 세 방향을 검사합니다 — 항등(`run_checks(input, input)`이 빈 리스트) · good 통과 · bad가 **선언된 코드를 최소한 포함해서** 실패. 

핵심은 `checks.py`의 설계 철학입니다: **정확한 문자열 기대가 아니라 방향성 게이트**. "출력이 이래야 한다"가 아니라 "알려진 실패 양상이 나타났는가" — 증가하면 안 되는 카운트, 사라지면 안 되는 구조 요소. 12개 안정 실패 코드(`hayeot_injection` · `heading_absorbed` · `footnote_anchor` · `quote_altered` · `number_injected` 등)가 API 계약입니다. 이 철학이 텍스트 밖에도 그대로 적용됩니다.

**CI.** studios 리포 최초입니다. im-not-ai 워크플로를 기반으로 확장:

```yaml
name: tests
on: [push, pull_request]
jobs:
  pytest:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.11", "3.12"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "${{ matrix.python-version }}" }
      - run: pip install pytest          # 유일한 서드파티 의존성
      - run: pytest tests/ -v
      - run: python3 scripts/build_quick_rules.py --check       # SSOT drift 차단
      - run: python3 scripts/build_diagnosis_rules.py --check   # 동일
      - run: python3 scripts/lint_skills.py skills/ agents/     # [신규] studios 자체 린트
```

테스트는 `unittest.TestCase`로 작성돼 있어 `python3 -m unittest`와 pytest 양쪽에서 돕니다. LLM 콜이 필요한 `test_humanize_live.py`는 `shutil.which("claude")`가 None이면 클래스 레벨 `skipIf`로 건너뛰므로 CI에서 안전합니다 — 다만 studios에서는 아예 제외하는 편이 깔끔합니다.

**`scripts/lint_skills.py` — 이번 통합에서 studios가 얻는 가장 실용적인 산물.** 현재 `skills/skill-test/SKILL.md`(356줄)는 7개 정적 검사를 정의하지만 **LLM이 읽고 수행하는 린터**라 CI에서 돌 수 없고, 사람이 명시적으로 부르지 않으면 아무 일도 안 일어납니다. 그 7개를 Python으로 옮기면:

1. 필수 프론트매터 5필드 존재 → FAIL
2. 번호 매긴 phase ≥2개 → FAIL
3. verdict 키워드 ≥1개(PASS/FAIL/CONCERNS/…) → FAIL
4. `allowed-tools`에 Write·Edit이 있으면 ask-before-write 문구 필수 → FAIL
5. next-step 핸드오프 → WARN
6. `context: fork`면 phase ≥5 → WARN
7. `argument-hint` 타당성 → WARN

**이 린터가 있었다면 업로드하신 스킬 3종이 1·2·3번에서 즉시 걸렸을 겁니다.** 그게 정확히 이 도구가 필요한 이유입니다. 에이전트 쪽도 같은 방식으로 5필드(`name`·`description`·`tools`·`model`·`maxTurns`)를 검사합니다. `skills/skill-test/SKILL.md`는 그대로 두되, 본문에 "정적 검사는 `scripts/lint_skills.py`가 SSOT이며 이 스킬은 그 위의 정성 평가를 담당한다"를 명기합니다.

참고로 `skill-test`가 참조하는 `CCGS Skill Testing Framework/quality-rubric.md`는 **리포에 존재하지 않습니다**(끊어진 참조). 이번에 같이 정리합니다.

### 4.5 A5 — 설치 스크립트 (부분 채택)

솔직하게 말씀드리면 **`install.sh`는 studios에 필요 없습니다.** im-not-ai가 이걸 갖는 이유는 Claude Code + Codex CLI + Gemini CLI 3개 타깃에 전역 심링크를 걸어야 하기 때문인데, studios는 이미 `marketplace.json`을 갖춘 마켓플레이스 플러그인이라 `/plugin install`이 그 일을 합니다. 전체 이식은 중복 설치 경로를 만들고 유지보수 부담만 늘립니다.

대신 **가치 있는 세 조각만** 가져옵니다.

`update.sh`의 `--check` 모드가 첫째입니다. upstream과 비교해 새 커밋이 있으면 **exit 10**, 최신이면 exit 0을 반환하는 결정적 인터페이스입니다. studios가 로컬 클론으로 개발되는 만큼 유용하고, 무엇보다 **exit code를 상태 신호로 쓰는** 이번 통합의 철학과 일치합니다.

`uninstall.sh`의 안전 규율이 둘째입니다. **"이 리포를 가리키는 심링크만 지운다"**(`[ -L "$dest" ] && [ "$(readlink "$dest")" = "$src" ]`, 아니면 "skip — 우리 것 아님"). 파괴적 작업의 모범 사례로, studios가 나중에 정리 스크립트를 쓸 때의 기준이 됩니다.

`tests/test_install_flags.sh`의 격리 실행 기법이 셋째입니다. `env -i HOME=$(mktemp -d) PATH=...`로 사용자 환경을 완전히 차단하고 `--dry-run`을 검증합니다. 향후 studios 훅 15개를 테스트할 때 그대로 쓸 패턴입니다.

이 세 개를 `docs/deterministic-gates.md`의 "채택한 패턴" 절에 기록하고, 실제 스크립트는 `scripts/update.sh`(--check 포함) 하나만 이식합니다. **install.sh/uninstall.sh 전체 이식은 권장하지 않습니다** — 필요하시면 넣겠습니다만, 지금은 뺀 상태로 계획을 세웠습니다.

## 5. 업로드 스킬 3종 편입

`design-encounters` · `audit-enemy-ai` · `verify-monster-contract`. INTEGRATION.md 기준 MengTo/Skills의 Three.js 게임 스킬 17종 중 방법론 성격이 강한 4종을 골라 3종으로 병합·일반화한 것이고, StarDiver 고유 수치와 Unity 종속성이 제거돼 있습니다. 내용 품질은 높습니다 — `design-encounters`의 "인카운터는 액터 수가 아니라 플레이어 결정의 연쇄다", "클리어 타임은 실패를 감추고 결정 지표는 드러낸다" 같은 판단은 studios의 기존 `/playtest-report` · `/balance-check`가 다루지 않는 층위입니다.

**문제는 형식입니다.** 세 파일 모두 프론트매터가 `name` + `description` 2개뿐이고, 번호 매긴 phase가 0개, verdict 키워드가 0개입니다. studios 정적 검사 7개 중 3개를 확정 FAIL 합니다. 필요한 수술:

| 항목 | 현재 | 변환 후 |
|---|---|---|
| 프론트매터 | 2필드 | 5필드 (`argument-hint` · `user-invocable` · `allowed-tools` 추가) |
| 섹션 | `## Compose` `## Keep it fair` `## Validate` `## Report` | `## 1. Compose` `## 2. Keep it fair` … 번호 부여 |
| verdict | 없음 | `## N. Report`에 PASS/CONCERNS/FAIL 명시 |
| ask-before-write | 없음 | `allowed-tools`에 Write 포함 시 필수 |

`verify-monster-contract`는 이미 본문이 "three verdicts"를 말하고 있어 단어만 studios 어휘(PASS / CONDITIONAL / FAIL)로 맞추면 됩니다. 나머지 둘은 Report 절을 판정 절로 승격시킵니다.

**팩 분류: 셋 다 `game`.** `allowed-tools`는 세 스킬 모두 `Read, Glob, Grep, Write, AskUserQuestion` 정도가 적절합니다(Bash 불필요).

**에이전트 연결.** studios 에이전트는 `skills:` 배열 필드를 지원하고 현재 12개가 사용 중입니다. INTEGRATION.md의 매핑을 그 필드로 구현합니다:

```yaml
# agents/game-designer.md     → skills: [design-encounters, ...]
```

## 8. 작업 방식

초안은 "마운트에 git 쓰기가 거부된다"는 전제 위에서 클라우드 작업을 권했는데, §1 다섯째대로 **그 전제가 틀렸습니다.** `index.lock` 잔여물을 지우니 로컬에서 커밋·머지가 정상 동작했고, Phase 0 세 커밋을 실제로 로컬에서 만들었습니다. 따라서 **전 단계를 로컬에서 진행합니다.**

Python 검증도 로컬에서 됩니다 — 이식 런타임이 표준 라이브러리만 쓰므로(§9 실측) `pytest`만 있으면 `pytest tests/ -v`와 `lint_skills.py`를 이 리포에서 직접 돌릴 수 있습니다. 클라우드로 우회할 이유가 없어졌습니다.

작업 순서에 대한 실무 원칙 세 가지만 둡니다.

- **Phase마다 커밋.** 각 Phase가 끝나면 검증 명령을 돌리고 그 출력이 통과한 상태로만 커밋합니다. 중간에 멈춰도 리포가 깨지지 않습니다.
- **push는 사용자 승인 후.** 현재 `main`이 `origin/main`보다 3 ahead인데 아직 push하지 않았습니다. 이후 커밋도 마찬가지로, 승인 전에는 로컬에만 둡니다.
- **Phase 1 전에 브랜치를 딸지 결정.** 리포 관행은 feature 브랜치 → PR 머지입니다(PR #1·#2·#3). Phase 0은 정리 작업이라 `main`에 직접 넣었지만, Phase 1부터는 변경 규모가 커서 `feature/v0.6.0-humanize-and-gates` 브랜치를 권합니다. (§11-1)

## 9. 리스크와 완화

**reference 316KB의 컨텍스트 부담.** `ai-tell-taxonomy.md` 하나가 77KB입니다. 다만 im-not-ai가 이미 v2.3에서 이 문제를 풀었습니다 — 진단 콜은 전량 대신 13KB 슬림 인덱스(`diagnosis-rules.md`, 83% 감축)를 읽고, 윤문 콜은 10KB `quick-rules.md`를 읽습니다. 전량을 읽는 건 taxonomist(유지보수)뿐입니다. **추가 대응 불필요**, 단 `docs/`에 이 구조를 명기해 나중에 누가 "그냥 taxonomy 읽게 하자"고 되돌리지 않게 합니다.

**첫 Python 도입.** 현재 리포는 markdown + bash + YAML만 있습니다. 완화: 이식 런타임 전체가 표준 라이브러리 전용(서드파티 0, Pillow 의존 스크립트는 제외 대상), CI가 3.11·3.12를 검증, 모든 스크립트가 실패 시 graceful degrade(`prepare_monolith_input.py`는 점수 계산이 깨져도 standard로 진행하고 `00_metrics.error`만 남깁니다). 훅은 전부 bash라 Python 부재가 세션을 깨지 않습니다.

**실측 검증 완료.** 이식 대상 9개 모듈의 import를 전수 확인한 결과 서드파티는 **0건**이었고(전부 `argparse` · `json` · `re` · `os` · `sys` · `difflib` · `statistics` · `collections` · `pathlib` · `hashlib` · `dataclasses`), live 테스트를 제외한 전체 스위트를 이 컨테이너에서 실제로 돌려 **185 passed, 1 skipped, 12 subtests — 1.08초**를 확인했습니다. CI에 넣어도 체감 부담이 없는 수준입니다.

**~~스킬 디렉터리에 부속 파일이 생기는 첫 사례~~ — 해소됨.** 초안에서 리스크로 잡았으나 §1 둘째대로 `web-ai-patterns`가 이미 선례이고 로딩 전략(인자로 파일 하나만 Read, 전량 덤프 금지)까지 확립돼 있습니다. `humanize-korean`은 규약 파괴가 아니라 두 번째 사례입니다. 남는 실무 항목은 **디렉터리명 단수화**(`references/` → `reference/`) 하나이고, §3.1의 grep 검증으로 잡습니다. 나머지 5개 신규 스킬은 단일 파일 관행을 지킵니다.

**`user-invocable: true` 전환으로 인한 자연어 오발동.** `humanize` · `humanize-redo`가 원래 명시 호출 전용이었습니다. 완화: description에 "명시적 슬래시 호출 전용" 명기, 관찰 후 v0.5.1에서 래퍼 통합 검토.
